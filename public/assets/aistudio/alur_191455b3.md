ALUR — Website Pengelolaan Galeri Foto Pengantin

1. Alur Utama

Admin login → Dashboard → Buat proyek → Isi data brand dan pengantin → Tambah galeri → Simpan draft → Pratinjau → Publikasikan → Sistem menyediakan link publik → Buat QR Code → Unduh PNG → Bagikan ke pengantin.

2. Alur Login Admin

1. Admin membuka halaman login.
2. Admin memasukkan email dan password.
3. Sistem memvalidasi kredensial melalui Supabase Auth.
4. Jika valid, admin diarahkan ke dashboard.
5. Jika tidak valid, sistem menampilkan pesan kesalahan.
6. Jika sesi berakhir, halaman pengelolaan meminta admin login kembali.

3. Alur Dashboard

1. Sistem memuat daftar proyek milik admin.
2. Dashboard menampilkan cover, nama pengantin, brand, status, dan tindakan proyek.
3. Admin dapat mencari proyek berdasarkan nama pengantin atau brand.
4. Admin dapat membuka proyek untuk diedit.
5. Admin dapat membuat proyek baru.
6. Admin dapat melihat halaman publik proyek yang sudah dipublikasikan.
7. Admin dapat mengarsipkan atau menghapus proyek sesuai hak akses.

4. Alur Membuat Proyek

1. Admin menekan tombol "Buat Proyek".
2. Sistem menampilkan form proyek.
3. Admin mengunggah gambar cover.
4. Admin mengunggah logo brand.
5. Admin mengisi nama brand.
6. Admin mengisi nama pengantin.
7. Admin mengisi atau memeriksa slug URL publik.
8. Admin menambahkan galeri.
9. Sistem memvalidasi semua data.
10. Sistem mengunggah cover dan logo ke Supabase Storage.
11. Sistem menyimpan data proyek ke tabel projects.
12. Sistem menyimpan setiap galeri ke tabel galleries dengan project_id yang sesuai.
13. Sistem menampilkan konfirmasi penyimpanan.

Jika validasi atau penyimpanan gagal, sistem menampilkan pesan kesalahan. Data yang sudah berhasil disimpan tidak boleh dianggap gagal seluruhnya tanpa memeriksa status penyimpanan sebenarnya.

5. Alur Pengelolaan Galeri

1. Admin membuka bagian galeri pada form proyek.
2. Admin menekan tombol "Tambah Galeri".
3. Sistem menampilkan form nama galeri dan link Google Drive.
4. Admin mengisi nama galeri, misalnya "Akad Nikah".
5. Admin memasukkan link Google Drive.
6. Sistem memvalidasi URL.
7. Admin dapat menambahkan galeri lain dengan cara yang sama.
8. Admin dapat mengubah nama, link, status aktif, dan urutan galeri.
9. Admin dapat menghapus galeri dengan konfirmasi.
10. Sistem menyimpan galeri dan menghubungkannya dengan proyek yang benar.

Satu proyek dapat memiliki satu atau banyak galeri. Setiap galeri mempunyai link Google Drive sendiri.

6. Alur Draft dan Publikasi

Simpan Draft

1. Admin menyimpan proyek sebagai draft.
2. Data proyek tersimpan.
3. Admin dapat membuka dan mengedit draft melalui dashboard.
4. Halaman publik aktif belum dapat diakses sebagai proyek terpublikasi.

Publikasikan

1. Admin memeriksa pratinjau halaman.
2. Sistem memastikan data wajib tersedia.
3. Sistem memastikan slug unik.
4. Admin menekan tombol "Publikasikan".
5. Sistem mengubah status proyek menjadi published.
6. Link publik menjadi aktif.
7. Sistem menampilkan link publik dan tindakan untuk membuat QR Code.

Kembali ke Draft

1. Admin memilih tindakan untuk menonaktifkan publikasi.
2. Sistem meminta konfirmasi.
3. Status proyek diubah menjadi draft.
4. Halaman publik tidak lagi menampilkan data proyek tersebut.

7. Alur Link Publik

1. Sistem menggunakan slug unik sebagai identitas URL.
2. Pengunjung membuka URL, misalnya "https://domain.com/p/andi-siti".
3. Sistem mencari proyek berdasarkan slug.
4. Sistem memeriksa status proyek.
5. Jika status published, sistem mengambil data proyek dan galeri aktif.
6. Sistem menampilkan halaman publik.
7. Jika proyek tidak ditemukan atau tidak dipublikasikan, sistem menampilkan halaman tidak tersedia.

Cover, logo, nama brand, nama pengantin, dan daftar galeri dapat diperbarui tanpa mengganti URL selama slug tetap sama.

8. Alur Halaman Publik

Urutan tampilan:

1. Cover proyek.
2. Logo brand.
3. Nama brand.
4. Nama pengantin.
5. Daftar kotak galeri aktif.
6. Footer brand jika digunakan.

Untuk setiap kotak galeri:

1. Pengunjung melihat nama galeri.
2. Pengunjung menekan kotak galeri.
3. Browser membuka link Google Drive yang sesuai.
4. Pengunjung melihat file sesuai izin berbagi Google Drive.

Jika Google Drive tidak mengizinkan akses publik, pengunjung mungkin diminta login atau meminta izin kepada pemilik file.

9. Alur QR Code PNG

1. Admin membuka proyek berstatus published.
2. Admin menekan tombol "QR Code".
3. Sistem mengambil URL publik proyek.
4. Sistem menghasilkan QR Code berdasarkan URL tersebut.
5. Sistem menampilkan pratinjau QR Code.
6. Admin dapat mengunduh file PNG.
7. Nama file mengikuti pola "qr-[slug-proyek].png".
8. Admin menguji QR Code dengan kamera HP.
9. Hasil pemindaian membuka halaman publik proyek yang benar.

QR Code tidak boleh hanya berupa gambar dekoratif. QR harus mengodekan URL publik yang valid.

QR Code dapat dibuat ulang kapan saja. Selama URL publik tidak berubah, QR Code lama dan baru tetap mengarah ke proyek yang sama.

10. Alur Berbagi ke Pengantin

1. Admin membuka detail proyek.
2. Admin menyalin link publik.
3. Admin mengunduh QR Code PNG.
4. Admin dapat membagikan link melalui WhatsApp.
5. Admin dapat mengirim file PNG atau mencetaknya.
6. Pengantin atau tamu membuka link atau memindai QR Code.
7. Halaman proyek dan galeri tampil.

11. Alur Edit Proyek

1. Admin memilih proyek dari dashboard.
2. Sistem memuat data proyek dan seluruh galeri.
3. Admin mengubah cover, logo, nama brand, nama pengantin, atau data galeri.
4. Sistem memvalidasi perubahan.
5. Sistem menyimpan perubahan.
6. Halaman publik menampilkan data terbaru.
7. URL publik tetap sama jika slug tidak berubah.
8. QR Code yang lama tetap berfungsi selama URL tidak berubah.

Jika slug akan diubah, sistem harus memperingatkan admin bahwa QR Code lama mungkin tidak lagi berfungsi. Jika memungkinkan, sediakan pengalihan dari slug lama ke slug baru.

12. Alur Hapus atau Arsip Proyek

Arsip

1. Admin memilih "Arsipkan".
2. Sistem meminta konfirmasi.
3. Status proyek berubah menjadi archived.
4. Halaman publik tidak lagi menampilkan proyek sebagai halaman aktif.
5. Data tetap tersimpan untuk kebutuhan pengelolaan internal.

Hapus

1. Admin memilih "Hapus Proyek".
2. Sistem menampilkan konfirmasi.
3. Sistem menghapus data galeri terkait dengan aman.
4. Sistem menghapus data proyek.
5. Sistem membersihkan file Storage yang terkait sesuai aturan.
6. Dashboard diperbarui.

Penghapusan harus dilindungi hak akses dan tidak boleh dijalankan hanya karena pengunjung membuka URL publik.

13. Struktur Relasi Data

projects

- Satu proyek memiliki satu cover.
- Satu proyek memiliki satu logo brand.
- Satu proyek memiliki satu nama brand.
- Satu proyek memiliki satu nama pengantin.
- Satu proyek memiliki satu slug publik.
- Satu proyek memiliki satu status.

galleries

- Satu galeri terhubung ke satu proyek melalui project_id.
- Satu proyek dapat memiliki banyak galeri.
- Satu galeri memiliki satu nama dan satu link Google Drive.
- Satu galeri memiliki status aktif dan urutan tampilan.

14. Keamanan dan Validasi

- Halaman dashboard hanya dapat diakses admin.
- Semua operasi tulis dilindungi autentikasi dan kebijakan RLS.
- Pengunjung publik hanya dapat membaca proyek published dan galeri aktif.
- Proyek draft atau archived tidak boleh terbuka melalui URL publik.
- Link Google Drive divalidasi sebagai URL yang sesuai.
- Upload cover dan logo dibatasi berdasarkan tipe dan ukuran file.
- Kunci rahasia backend tidak boleh ditempatkan di frontend.
- QR Code hanya dibuat dari URL publik proyek yang benar.

15. Skenario Pengujian

1. Admin berhasil login.
2. Admin gagal login dengan kredensial yang salah.
3. Admin membuat proyek baru.
4. Admin mencoba menggunakan slug yang sudah dipakai.
5. Admin menambahkan tiga atau lebih galeri.
6. Admin mengubah link Google Drive salah satu galeri.
7. Admin menyimpan draft dan memastikan halaman publik belum aktif.
8. Admin mempublikasikan proyek dan membuka URL publik.
9. Admin membuat QR Code PNG.
10. QR Code dipindai dan membuka proyek yang sesuai.
11. Admin mengubah cover tanpa mengubah slug.
12. QR Code lama tetap membuka proyek yang benar.
13. Pengunjung mencoba membuka proyek draft.
14. Pengunjung mencoba melakukan operasi edit.
15. Pengunjung menekan galeri dan membuka Google Drive.
16. Tampilan diuji pada HP, tablet, dan desktop.
17. Sistem menangani URL salah, file terlalu besar, dan kegagalan jaringan.

16. Hasil Akhir yang Diharapkan

Admin memiliki satu dashboard untuk mengelola banyak proyek pengantin. Setiap proyek mempunyai identitas brand, cover, nama pengantin, banyak kotak galeri, satu link publik unik, serta QR Code PNG yang siap dibagikan dan dicetak.
